# 跨所套利工作台（Cross-Venue Arbitrage）

> **核心理念：当同一真实世界二元事件在两个交易所同时挂牌，且 `A 腿卖一 + B 腿反向卖一 + 双腿 Taker 手续费` 低于 `$1.00` 并超过开仓阈值 `spread_open_pct` 时，双腿等量锁仓；无论哪一方结算胜出，到期兑付恒为 `$1.00`，收益在入场瞬间锁定。**

跨所套利不同于传统单交易所策略：它同时跨越 **A / B 两个交易所账户**、受制于**双方共同支持的时间轮次交集**，且收益与风险必须按**双腿合并视角**观测。BlitzkriegBot 将跨所套利独立为与「策略」「智能交易」平级的专属工作台（`策略 → 套利`）。

---

## 一、核心能力与工作流

1. **双腿绑定与共同轮次锁定（`arb.config.set`）**
   - 绑定 A 腿（如 `polymarket` 账户）与 B 腿（如 `kalshi` 账户）以及监控币对（如 `BTC` / `ETH` / `SOL`）。
   - **自动求轮次交集**：内核自动计算两家交易所支持的时间轮次交集（例如 A 交易所支持 `5m / 15m / 1h`，B 交易所仅支持 `15m`，系统自动锁定并跟随 `15m` 共同轮次；若无共同周期则 fail-closed 拒收，避免跨周期错配）。
   - 支持一键解除套利配置（`arb.config.clear`）；当任意一条腿对应的账户执行「重置交易」时，内核自动清理失效的套利绑定。
2. **6 项运行就绪体检（`arb.status`）**
   - 工作台实时展示 6 项前置条件状态：双腿配置、共同轮次周期、A 腿账户状态、B 腿账户状态、套利引擎开关、双腿实时盘口在线率。
   - 任一前置未就绪（如单侧账户未开交易、风控冻结、行情断流或总开关暂停）都会明确标红并指出原因。
3. **实时跨所价差扫描板（扣费净空间 vs 开仓阈值）**
   - 实时呈现每个监控币对在共同轮次下的 A/B 两侧 `UP / DN` 卖一价、`A_UP + B_DN` 与 `A_DN + B_UP` 组合成本、**毛空间**（`$1.00 - 最优组合成本`）以及**扣费净空间**（扣除双腿 Taker 手续费后的真实净空间）。
   - **真实阈值对齐**：扫盘板直接读取 `cross_venue_arb` 当前生效的 `spread_open_pct`（默认 `2.00%`，即净空间 `≥ +2.00¢`），仅当扣费净空间达到触发线时才高亮为绿色「可触发」，彻底避免「毛空间刚过 `0¢` 标绿但策略按设计未下单」的误解。
4. **双腿合并账务与 PairBook 追踪**
   - 顶部 KPI 与底部三页签（**活跃配对 PairBook** / **套利订单** / **历史成交**）跨 A、B 两个账户自动聚合净盈亏、胜负统计与成交明细，消除单账户视角下套利盈亏割裂的问题。

## 二、触发条件与参数说明

`cross_venue_arb` 策略在每轮评估中遵循以下 fail-closed 规则：

| 参数 / 条件 | 默认值 | 说明 |
| --- | --- | --- |
| `spread_open_pct` | `2.00`（`2%`） | 开仓门槛：要求 `ask_UP + ask_DOWN + 双腿 Taker 手续费 ≤ 1.00 - spread_open_pct / 100` |
| `spread_close_pct` | `0.50`（`0.5%`） | 回落平仓释放阀：持仓后若全成本回升至距 `$1.00` 不足 `Y%`，允许按各自买一价释放 |
| `min_pair_shares` | `1` | 容量取两平台可见卖一深度的最小值（`min(depth_A, depth_B)`），低于该值不开仓 |
| `min_time_left_sec` | `30` 秒 | 距本轮结算剩余时间低于该值时不再开新配对 |
| `min_leg_price` / `max_leg_price` | `0.01` / `0.99` | 单腿卖一价越界保护，拒绝极端异常报价 |
| `atomic_batch` | `true` | 原子批次预占：双腿作为一张经济票据预占虚拟额度，超限则整对取消，杜绝单腿裸奔 |

## 三、架构与接口契约

| 层级 | 组件 / 接口 | 说明 |
| --- | --- | --- |
| 套利配置与状态 IPC | `arb.config.set` / `arb.config.get` / `arb.config.clear` / `arb.status` | 位于 `core/blitzkrieg_core/src/ipc/server/handlers/arb.rs`，提供共同轮次锁定、6 项就绪体检、扣费扫盘快照与双腿聚合记录 |
| 扫盘快照引擎 | `Engine::arb_scanner_snapshot` | 按锁定的 `round_duration_sec` 对齐双腿实时盘口，复用内核统一 `FeeSchedule` 计算双腿 Taker 手续费与净空间 |
| 策略包与配对账本 | `user_layer/strategies_lua/cross_venue_arb` + 内核 `PairBook` | 以 `(instance, asset, slot)` 为经济去重键，单腿未成可补腿，轮次切换自动闭账 |
| WebUI 工作台 | `策略 → 套利`（`ArbitragePage.vue` + `CreateArbDialog.vue`） | 独立于单交易所策略页，实时联动面板心跳刷新 |

## 四、使用提示

- 首次使用请先确认 A / B 两个交易所账户均已在「设置 → 账户」中绑定对应场地并开启交易，且资金与风控限额充足。
- 若扫盘板显示某币对**毛空间为正但标注「未达阈值」**，说明扣除双腿手续费后的净空间尚未达到 `spread_open_pct`（默认 `2.00%`），策略保持静默属于正常行为。
- 更多底层验收与架构细节见 [`arb-arch-acceptance.md`](/arb-arch-acceptance) 与 [`cross-arb-acceptance.md`](/cross-arb-acceptance)。
